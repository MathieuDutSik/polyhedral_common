# The dimension-5 packing-covering record

The packing-covering constant of a point set `X` is

    gamma(X) = mu(X) / rho(X)

with `mu` the covering radius and `rho` the packing radius. Minimising it is
the Schuermann-Vallentin problem. Over LATTICES the optimum is known in small
dimension; in dimension 5 it is Horvath's `Ho_5`, with

    gamma_5 = sqrt(3/2 + sqrt(13)/6) = 1.4494568681327953...

The configuration recorded here is a 2-periodic NON-LATTICE point set with
`gamma < gamma_5`, so the dimension-5 problem is not solved by a lattice.

## The files

| file | what it is |
| --- | --- |
| `Gram_witness`, `Cosets_witness` | the RATIONAL witness, denominator `10^5` |
| `FileDesc10` | the degree-10 real field of the exact optimum |
| `Gram_record` | the exact optimum `A_0`, over that field |
| `Cosets_record` | the coset of the exact optimum, over that field |

`../run_packing_covering_record.sh` runs `LATT_SerialPeriodicDelaunay` on the
witness and checks the inequality exactly.

## The witness, and why it is the thing that gets checked

The witness is the optimum rounded to denominator `D = 10^5`. It is not an
approximation used in place of the optimum: it is a legitimate periodic point
set in its own right, so `gamma < gamma_5` for it is a complete statement, and
being rational it is settled by exact arithmetic with no perturbation argument.
It attains

    lambda^2 = 67111869007031/250000000000000
    gamma    = 1.4472855...

a little worse than the optimum below, and still under `gamma_5`.

## The exact optimum

The optimum is an isolated solution of its active-constraint system -- 48 of
the 240 Delaunay orbits attain `mu`, 10 orbits of inter-point vectors attain
`lambda` -- so it is a single point and its coordinates are algebraic. With
`lambda^2 = 1`,

    X = Z^5 + {0, c},   c = (1/2, x, -1/2, 1/2, 1/2)

where `x = -1.21596602392453632254176375495569316860859451509299...` has
degree 10. `FileDesc10` describes the field through the generator

    v = -4 x = 4.86386409569814529016705501982277267443...

which is positive, as the real-field machinery requires, and an algebraic
integer, its minimal polynomial being monic:

    v^10 - 124 v^9 + 5460 v^8 - 110916 v^7 + 1248898 v^6 - 8647850 v^5
        + 40019171 v^4 - 135242256 v^3 + 349657808 v^2 - 619542528 v
        + 525026304 = 0

`Gram_record` is `A_0` written over this field, entry by entry, in the
polynomial syntax the field parser reads (its generator is spelled `x` there,
so `x` in those files means `v`, and the record's `x` is `-1/4*x`). It was
obtained from

    u = 4 x^2 + 8 x
    p = (2358 + 13131 x + 5388 x^2 - 36896 x^3 - 52896 x^4 - 25472 x^5
         - 4096 x^6) / (6 (101 - 920 x - 2652 x^2 - 2144 x^3 - 512 x^4))

    A_0 = [ -9/4-3p-u     3/2      p           27/4+4p-u    u-p        ]
          [  3/2          1       -1            1/2         1          ]
          [  p           -1      -2-2p         -7/2-2p     -5/2-p      ]
          [  27/4+4p-u    1/2    -7/2-2p        7/4-u+p    -11/2-4p+u  ]
          [  u-p          1      -5/2-p       -11/2-4p+u    4+2p-u     ]

and reproduces the independently computed numerical optimum.

    mu^2  = 0.5231212420153514632152715204641506307757
    gamma = 1.4465424183415451619146480446414739612341

## Why the program does not read the last three files yet

Two separate obstructions, and only the first is a gap to be filled.

1. An algebraic FORM needs the field type to work on the lattice side.
   `RealField` has no nearest-integer rounding and no conversions to and from
   the integers, both of which the LLL reduction calls, and
   `FundamentalDelaunay.h` adds a Graver vector to a vertex without a
   conversion -- which compiles only because `mpq_class` carries mixed-type
   operators. The first of these is upstream, in `basic_common_cpp`.

2. An algebraic COSET is not reachable by patching. A periodic point set is
   represented here as a union of cosets of a finite-index sublattice of
   `Z^n`, so it is contained in a lattice by construction. Here the group
   generated by `X` is `Z^5 + Z c`, and since `c` is not a torsion point of
   `R^5/Z^5` -- its second coordinate `x` is irrational -- that group is
   dense. The point set lies in no lattice at all, so no choice of basis or
   denominator puts it in the coset formalism. This is why the exact
   inequality is established on a rational point set instead.
